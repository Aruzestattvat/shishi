从微信聊天里找出你答应过的日程和待办，把**明确属于你**的事项自动写进「苹果提醒事项」（选择 iCloud 清单可跨设备同步），不确定的先放进「待查看」等你核对。

- 版本：**1.9.1** · 分支 `main`（本地应用 `local.shishi.app`）
- 安装位置：`/Applications/拾事.app`
- 工作目录：`本仓库根目录`
- 交接来源：早期由 Codex 搭出雏形，之后继续完成规则、界面与验收。

## 下载

从 [Releases](https://github.com/Aruzestattvat/shishi/releases) 下载打包好的 macOS arm64 应用，或直接使用源码构建。

## 这次补齐了什么

Codex 留下的版本能启动、能出界面，但实际是「半成品」：分析链路遇到一条模型结果就永久卡死，窗口关掉再从 Dock 打开会崩溃。本次完成的内容：

1. **修复分析永久卡死**：临时错误自动退避重试，额度/密钥/权限才暂停；不再无限等待。
2. **修复单条脏数据卡死整批**：非法模型结果只跳过该条并记录原因。
3. **批量分析 + 回看范围**：60 条一批；新增 7/30/90/365 天/全部历史；放宽范围会自动重扫跳过项。
4. **修复关闭窗口后崩溃**：窗口不随关闭释放，Dock 重开不再访问野指针。
5. **退出即停后台**：`server.pid` 管理，退出 App 一并结束后台；重复启动复用已在运行的后台。
6. **权限体验**：重装后首次启动自动请求提醒事项权限。
7. **界面**：独立滚动侧栏、同步/回看/用量信息、隐藏旧事项提示、无成功弹窗。
8. **聊天头像框**：头像按需下载缓存，列表刷新不闪烁。
9. **修复新消息同步**：新增列后同步 SQL 列数不匹配导致新消息失败，已改为显式列名并加测试。
10. **公众号移除 / 微信置顶**：公众号不进入选择列表；置顶会话排最前并用加深背景块表示。
11. **日期判断 / 仅记录新消息**：默认只分析起始日期之后的新消息；旧待查看自动隐藏；日期判断可调整。
12. **点击完成 / 恢复待办**：单击待办圆圈或条目即完成；已完成可恢复；状态写回提醒事项。
13. **菜单栏**：纯图标；一级菜单直接列待处理事项 + 最下面「打开仪表盘」，无二级菜单。
14. **后台常驻**：`LSUIElement` 菜单栏模式，无 Dock 图标、启动不弹窗口，关闭窗口后继续运行。
15. **本地语音转写**：选中聊天里的新语音用本机 **Qwen3-ASR 0.6B** 转文字再分析，不调用云端 ASR；转写进程结束即释放模型内存。语音来源的证据带「语音转写」标记，事项默认仍需核对。

17. **双方确认**：我提出具体安排、对方回复「可以的/好的/OK」也可形成承诺自动记下；知悉、条件、群内答复仍需核对。
16. **无具体时刻也直接记下（保留时间前缀）**：明确答应、原文没有具体钟点（如「今晚和对方聊天」）时自动记入待办；有时刻就保留时刻，只有日期就按日期记，不再因为 `time_uncertain` 卡在待查看。原文有日期线索但解析不出日期（如「明天」却无日期）仍会待核对。

17. **点击完成立即移动**：在仪表盘点完成/恢复时先本地乐观更新，事项立刻移到「已处理」/「待办」，后台同步完成前不会停留在原位置或闪回。

## 使用

1. 打开「拾事」，在左栏勾选要留意的聊天，点「保存选择并开始」。
2. 「苹果提醒事项」面板里确认已连接；可选 iCloud 清单，默认会创建/使用「拾事 · 微信待办」。
3. 等待分析（状态栏会显示进度）。结果分三类：
   - 你针对具体安排明确回复「好的 / OK / 可以」等 → 自动加入提醒；
   - 你还没回复，或答复对不上具体事项 → 进入「待查看」；
   - 你明确拒绝 → 不加入。
4. 「待查看」里可修改标题/日期后「核对并加入」，或直接「忽略」。
5. 左侧「仅记录新消息」默认开启：只看所选起始日期（默认今天）之后的新消息，更早聊天不记录。关闭后可用「回看多久的聊天」分析最近 7/30/90/365 天或全部历史。

## 数据与隐私

| 内容 | 位置 |
|---|---|
| 本地数据库 | `~/Library/Application Support/Shishi/shishi.sqlite3` |
| 原生桥接 | `~/Library/Application Support/Shishi/bridge/`（请求/响应/status.json） |
| 头像缓存 | `~/Library/Application Support/Shishi/avatars/`（按会话缓存，约几十 KB/个） |
| 日志 | `~/Library/Application Support/Shishi/app.log`、`selftest.log` |
| 密钥 | `~/.config/wvbar/secrets.env`（`ALPHA_TOKEN`、`DEEPSEEK_API_KEY`） |
| 本地页面 | http://127.0.0.1:8766 （也可在浏览器打开；仅本机） |

- 微信内容来自本机 Alpha 的 HTTP API（`127.0.0.1:5031`），不上传微信账号。
- 先在本地用关键词筛候选，只有候选和必要上下文会发给 DeepSeek；结果按内容哈希缓存，不重复调用。
- 模型没有直接写系统的能力：每条事项都要逐字证据校验，写提醒事项由原生 EventKit 完成。

## 构建与测试

```bash
cd 本仓库根目录
python3 -m unittest -v test_shishi.py     # 55 项本地测试
python3 evaluate.py                       # 可选：少量合成对话验证真实模型规则
python3 build.py                          # 只构建到 ./dist/拾事.app
python3 build.py --install                # 构建并替换 /Applications/拾事.app
```

自检（页面加载 → 关窗 → 重开不崩溃）：

```bash
"/Applications/拾事.app/Contents/MacOS/Shishi" --selftest
# 结果同时写入 ~/Library/Application Support/Shishi/selftest.log
```

依赖：Xcode 命令行工具（Swift 6.3 可配 `MacOSX26.5.sdk`）、系统 `/usr/bin/python3`，无需第三方 Python 包。Alpha 需在运行且开启「主动推送」，本机 `127.0.0.1:5031` 可用。

## 调试

- `GET http://127.0.0.1:8766/api/health`：存活与版本
- `GET http://127.0.0.1:8766/api/state`：会话/事项/用量/回看范围
- `GET http://127.0.0.1:8766/api/debug`：线程心跳、重试状态、最近错误
- 后台重复启动会在 `app.log` 写入「拾事后台已在运行」；如异常残留可删除 `~/Library/Application Support/Shishi/server.pid` 后重启 App。

## 已知限制

- 语音会用本机 Qwen3-ASR 转写（仅选中聊天、日期范围内）；图片、文件、表情等仍不处理，界面会显示未完整覆盖数量。语音转写可能有误差，相关事项默认进入待查看。
- 群聊里的「大家」安排不会自动加入，需出现 @你/明确指向你的内容。
- 默认只回看 30 天，更早消息需要手动放宽「回看多久的聊天」。
- 年龄久远、时间已过的事项会进入「待查看」并提示核对。
- 重装（重新签名）后 macOS 会重置提醒事项授权，需要点一次系统弹窗。
